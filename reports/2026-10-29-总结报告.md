### 提交 `703a22d` — UI 大改版 + 前端 5 处存量 bug

**UI 重做**（纯标准库单文件不变，保留全部 API 逻辑与选择器契约）：
- 顶部导航+表格堆叠 → 固定侧边栏（SVG 图标 + 环境状态卡）+ 页头，窄屏自适应
- 总览：执行控制卡（状态胶囊着色）+ 三统计瓦片（体力环形进度）+ 计划步骤时间线 +
  追猎/推演卡片 + 日志终端（按级别着色）
- 全局：toast 与自定义确认框替代 alert/confirm；设置页开关组件；材料卡片网格；
  空状态提示；等宽数字排版

**顺手修复的存量前端 bug**：
1. 未决执行「已核对库存/放弃记账」按钮从未绑定事件（点击无反应）→ 接入 /api/reconcile
2. 总览调 GET /api/plan 而后端仅 POST 路由 → **日常计划从未真正显示过**；后端补只读 GET 路由
3. 需求表编辑器 `.map(bandRow(b=>b))` 立即求值抛 TypeError → 编辑器永远空白且后续保存按钮全部失灵
4. 首次加载（兼容检测约 3s）期间点导航在 BOOT 未就绪时报错并被总览覆盖 → 记录目标页
5. `api()` 加 15s AbortSignal 超时，网络挂死不再无限空白

### 提交 `ce28a13` — 加载性能优化

- `OkNte.is_running()` 拆出 `_detect_running()`，结果入**类级** 5s 缓存（须类级：面板每请求
  新建实例）；`is_running_cached()` 供展示类调用复用；启动时后台线程预热
- **安全边界**：写配置前检测（write_anomaly_config / ensure_routine_item / runner 执行前）
  保持实时，绝不用缓存
- 实测：bootstrap 首次 2.9s → 之后 0.016s（原每次 2.5-2.8s）；plan 原 2.45s → 0.016s
